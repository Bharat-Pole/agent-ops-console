# Incident Response Coordinator

Coordinates sub-agents to triage major incidents: log analysis, impact, comms drafting, and notification routing.

Generated by **agent_forge** (spec → code) from the Brightspeed agent-ops-console
canonical config. Topology: **supervisor**. Model: **gemini-1.5-pro**
via **Google AI Studio**.

> The generator is deterministic (no LLM used to generate this code). The agent
> itself uses Gemini at runtime.

## Run

```bash

pip install -r requirements.txt
cp .env.example .env      # then fill in credentials
python -m agt_incident_response_coordinator_20260205_c3d9.rag.ingest        # build the local vector index from src/agt_incident_response_coordinator_20260205_c3d9/rag/sample_docs

```

Structural test (no API key needed): `pytest`

## LLM target

Generated for **Google AI Studio** (`ChatGoogleGenerativeAI`, `GOOGLE_API_KEY`).
The config's `vertex://` prefix is normalized away. To emit real Vertex code
(`ChatVertexAI`), regenerate with `--llm-target=vertex`.

## Advisory-only scope (LOCKED)

Only read/summarize/draft/recommend/validate tools are bound. Write-capable tools
are emitted **disabled** in `tools.py` (they raise `PermissionError`) and are never
bound to the agent.
Disabled write tools: `email_sender`, `slack_notifier`.
Enable one only behind a human-in-the-loop gate after governance approval.

## Human-process gates (not graph interrupts)

score_threshold=0.75) built lazily from the bundled sample docs
in `src/agt_incident_response_coordinator_20260205_c3d9/rag/sample_docs/` — no native deps, runs out of the box. Referenced
sources: kb://incident-db-prod-v3@v3. For a persistent/managed

`vector://alloydb-incidents`).
